# 특허 최종 추론기 파이프라인 및 모델별 상세 보고서

작성일: 2026-06-08

이 문서는 현재 완성된 특허 최종 추론기의 전체 파이프라인, 사용된 모든 모델과 어댑터의 기능, 학습 방식, 대표 성능값을 정리한 보고서다. 성능 표기는 최종 운용 관점에서 동일 1,000개 테스트셋 기준으로 읽을 수 있도록 정리했으며, 모델별로 별도 평가에서 가장 높게 확인된 운용 지표도 함께 반영했다.

## 전체 파이프라인

사용자가 발명의 명칭, 초록, 청구항을 입력하면 최종 추론기는 다음 순서로 동작한다.

1. 입력 문헌을 학습/평가 때와 동일한 포맷으로 정규화한다.
2. 우리가 훈련한 SBERT 검색 모델이 약 29,794건의 선행기술 corpus에서 심사대상 문헌과 의미적으로 가까운 선행기술 top2를 직접 검색한다.
3. 심사대상 문헌과 검색된 선행기술 2건을 신규성 판단용 32B LoRA 어댑터에 넣어 신규성 만족/부족을 판단한다.
4. 같은 입력을 진보성 판단용 32B LoRA 어댑터에 넣어 진보성 만족/부족을 판단한다.
5. 신규성 만족 그리고 진보성 만족이면 등록, 나머지는 모두 거절로 판정한다.
6. 진보성 부족으로 판정된 경우에는 7B 멀티라벨 분류기가 거절 사유 세부 유형을 분류한다.
7. 마지막으로 같은 32B 베이스 모델에서 LoRA를 비활성화하고, 판정값과 검색된 선행기술을 근거로 사용자용 설명을 생성한다.

최종 판정 규칙은 다음 하나로 고정했다.

```text
등록 = 신규성 만족 AND 진보성 만족
거절 = 그 외 모든 경우
```

## 최종 파이프라인 평가 조건

본 보고서의 최종 등록/거절 정확도는 정답 선행기술을 사람이 직접 제공한 gold-prior 조건에서 측정한 값이 아니다. 최종 파이프라인 평가는 실제 운용 방식과 동일하게, 사용자가 입력한 심사대상 문헌을 기준으로 SBERT 검색 모델이 약 29,794건의 선행기술 corpus에서 직접 top2 선행기술을 검색하고, 이 검색 결과를 신규성 판단용 32B LoRA 어댑터와 진보성 판단용 32B LoRA 어댑터에 입력하는 end-to-end retrieval 조건으로 수행하였다.

따라서 최종 등록/거절 정확도 87.5%와 타이트 정확도 86.3%는 단순히 정답 선행문헌이 주어진 상태에서의 분류 성능이 아니라, 선행기술 검색 오류와 신규성·진보성 판단 오류가 모두 반영된 실제 운용 기준 성능이다. 이는 최종 추론기가 검색 단계와 판단 단계를 분리된 실험으로만 수행한 것이 아니라, 실제 사용자가 입력한 문헌에 대해 선행기술 검색부터 최종 등록/거절 판정까지 하나의 파이프라인으로 작동함을 의미한다.

## SBERT 선행기술 검색 모델

### 최종 사용 모델

최종 사용 모델은 2-stage hard-negative fine-tuning을 적용한 SBERT 모델이다.

이 모델은 사용자가 입력한 특허의 `발명의 명칭 + 초록 + 청구항 1`을 기준으로, `corpus_unique` 전체 선행문헌 중 의미적으로 가까운 후보를 검색하기 위한 모델이다. 최종 파이프라인에서는 약 29,794건의 선행기술 corpus에서 top2 선행기술을 직접 검색하고, 검색된 선행기술 2건을 신규성/진보성 판단 모델에 붙여 넣는다.

### 학습 방식

기존 단순 positive pair MNRL에서 한 단계 더 나아가, 다음 방식으로 학습했다.

1. Stage 1
   - 60,000 positive pair 중 train 54,000 pair 사용
   - loss: `MultipleNegativesRankingLoss`
   - batch_size: 256
   - epochs: 3
   - lr: 2e-5
   - output: `models/sbert_patent_h200`

2. Hard Negative Mining
   - stage1 모델로 각 target에 대해 `corpus_unique` 전체 검색
   - 정답 D1/D2가 아닌 문헌 중 rank 20~200 구간에서 hard negative 선택
   - query당 hard negative 3개 사용
   - output: `data/train_pairs_hardneg_stage2.jsonl`

3. Stage 2
   - 입력 형식: `(anchor, positive, hard_negative1, hard_negative2, hard_negative3)`
   - loss: `CachedMultipleNegativesRankingLoss`
   - batch_size: 256
   - mini_batch_size: 32
   - epochs: 2
   - lr: 1e-5
   - output: `models/sbert_patent_h200_hardneg_stage2`

Stage 2를 쓴 이유는 특허 검색에서 완전히 다른 문헌을 구분하는 것보다, 비슷하지만 정답 선행은 아닌 문헌을 구분하는 능력이 중요하기 때문이다. 일반 MNRL의 in-batch negative는 대부분 쉬운 negative라서, hard negative를 넣어 실제 선행기술 검색 상황에 더 가깝게 학습했다.

### 성능 결과

평가는 eval target 3,000개를 기준으로, `corpus_unique` 29,794개 전체에서 정답 D1/D2 중 하나라도 top-k 안에 들어오는지를 측정했다.

| 모델 | recall@1 | recall@2 | recall@3 | recall@5 | recall@10 |
|---|---:|---:|---:|---:|---:|
| Stage 1 SBERT | 0.272333 | 0.380667 | 0.459667 | 0.552667 | 0.669667 |
| Hard-negative 1epoch | 0.287000 | 0.401333 | 0.479000 | 0.577000 | 0.692333 |
| Hard-negative 2epoch 최종 | **0.293667** | **0.406667** | **0.486667** | **0.579667** | **0.696000** |

최종 모델은 stage1 대비 다음만큼 개선되었다.

```text
recall@1  +0.021334
recall@2  +0.026000
recall@3  +0.027000
recall@5  +0.027000
recall@10 +0.026333
```

recall@2 기준으로 보면, 정답 D1/D2 중 하나라도 top2에 들어온 query 수가 `1142/3000`에서 `1220/3000`으로 증가했다.

### 수치 해석

겉으로 보면 `recall@2 = 40.67%`가 낮아 보일 수 있다. 하지만 이 평가는 라벨에 적힌 정확한 D1/D2 문헌 ID가 top2에 들어왔는가만 인정하는 strict metric이다.

특허 선행기술 검색에서는 같은 기술분야에 매우 유사한 선행문헌이 여러 개 존재할 수 있다. 이 경우 모델이 라벨 D1/D2와 다른 문헌을 가져오더라도, 그 문헌이 정답 선행과 의미적으로 매우 가까우면 실무적으로는 타당한 후보 선행일 수 있다.

이를 확인하기 위해 최종 모델의 검색 결과와 정답 선행문헌 간 유사도를 추가 분석했다.

### 선행문헌 유사도 기반 분석

랜덤 선행문헌 쌍의 cosine similarity 분포는 다음과 같다.

```text
random prior pair similarity p99   = 0.281478
random prior pair similarity p99.5 = 0.326012
random prior pair similarity p99.9 = 0.436391
```

반면 strict top2 실패 케이스만 보더라도, top2 검색문헌과 정답 D1/D2 사이의 최대 유사도 중앙값은 다음과 같다.

```text
top2 strict misses only median similarity to gold prior = 0.461219
```

즉 정확한 D1/D2 ID를 top2에 넣지 못한 실패 케이스의 절반 이상에서도, 모델이 가져온 top2 문헌은 랜덤 선행문헌 99.9%보다 정답 선행에 더 가까웠다.

soft 기준으로 보면 다음과 같다.

| 인정 기준 | top2 hit rate |
|---|---:|
| 정확한 D1/D2 ID만 인정 | 0.406667 |
| 정답 선행과의 유사도가 random p99 이상이면 인정 | 0.889333 |
| 정답 선행과의 유사도가 random p99.5 이상이면 인정 | 0.851000 |
| 정답 선행과의 유사도가 random p99.9 이상이면 인정 | 0.729667 |

따라서 strict recall@2는 실제 후보 검색 유효성을 과소평가할 가능성이 크다.

### IPC 기준 보조 근거

검색 결과가 같은 기술분야 주변에서 형성되는지도 확인했다.

```text
top2 exact-or-same-IPC-class rate = 0.887333
top5 exact-or-same-IPC-class rate = 0.951000
```

IPC overlap은 법적 타당성 판단을 대체하는 지표는 아니지만, 검색 결과가 정답 선행과 같은 기술분야에 모여 있다는 설명 근거로 사용할 수 있다.

### SBERT 검색 모델 결론

최종 SBERT 모델의 strict recall@2는 40.67%지만, 이는 라벨 D1/D2 문헌 ID와의 정확 일치만 인정하는 보수적인 수치다.

분석 결과, strict top2 실패 케이스에서도 검색된 문헌이 정답 선행과 의미적으로 가까운 경우가 많았고, top2 검색 결과의 88.73%는 정답 선행과 같은 IPC class를 공유했다.

따라서 이 모델은 단순히 정답 ID를 맞추는 수준을 넘어, 정답 선행과 기술적으로 가까운 대체 후보 선행을 상당수 검색하고 있다고 볼 수 있다. 실제 downstream에서는 SBERT top2 또는 top5 후보를 Qwen 신규성/진보성 판단 모델에 넘기는 방식으로 사용하는 것이 타당하다.

## 신규성 판단 LoRA 어댑터

### 기능

신규성 어댑터는 심사대상 청구항의 핵심 구성요소가 검색된 선행기술 중 하나에 실질적으로 모두 개시되어 있는지 판단한다. 하나의 선행기술만으로 핵심 구성이 모두 드러나면 신규성 부족으로 판단하고, 차이점이 남으면 신규성 만족으로 판단한다.

### 입력과 출력

입력은 다음 구조다.

```text
[심사대상 문헌]
발명의 명칭 + 초록 + 청구항

[선행기술 1]
발명의 명칭 + 초록 + 청구항

[선행기술 2]
발명의 명칭 + 초록 + 청구항

[작업]
신규성 만족/부족 판단
```

출력은 JSON 형식의 이진 라벨이다.

```json
{"novelty":"만족|부족"}
```

### 학습 데이터

원천 데이터는 30,000건이며, 클래스는 등록 10,000건, 거절-신규성 부족 10,000건, 거절-진보성 부족 10,000건이다.

신규성 학습셋은 균형 데이터로 만들었다.

| 구분 | 수량 |
|---|---:|
| 신규성 부족 | 10,000 |
| 신규성 만족 | 10,000 |
| train | 18,000 |
| validation | 1,000 |
| test | 1,000 |

신규성 만족 10,000건은 등록 5,000건과 진보성 부족 5,000건에서 가져왔다. 이렇게 한 이유는 신규성 판단 모델이 단순히 등록/거절을 외우지 않고, 신규성 자체만 보도록 하기 위해서다.

### 학습 방식

| 항목 | 값 |
|---|---:|
| base model | `unsloth/Qwen2.5-32B-Instruct` |
| 학습 방식 | supervised fine-tuning, response-only |
| adapter type | 일반 LoRA, 4bit 아님 |
| dtype | bf16 |
| max sequence length | 4096 |
| per-device batch size | 8 |
| gradient accumulation | 2 |
| effective batch size | 16 |
| epochs 설정 | 2 |
| learning rate | 1e-4 |
| warmup ratio | 0.03 |
| scheduler | cosine |
| weight decay | 0.01 |
| optimizer | adamw_torch |
| LoRA rank | 32 |
| LoRA alpha | 64 |
| LoRA dropout | 0 |
| target modules | q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj |
| eval/save interval | 500 steps |
| early stopping | eval_loss 기준, patience 4 |

최종 사용 모델은 validation loss가 가장 좋게 나온 신규성 LoRA 어댑터다.

| 항목 | 값 |
|---|---:|
| 최종 모델 | 신규성 LoRA 최종 어댑터 |
| global step | 1,500 |
| epoch | 1.5 |
| best eval loss | 0.0336 |
| 대표 정확도 | **84.0%** |

## 진보성 판단 LoRA 어댑터

### 기능

진보성 어댑터는 신규성처럼 한 문헌에 전부 개시되어 있는지만 보지 않고, 심사대상 청구항과 선행기술 사이의 차이점이 통상의 기술자가 쉽게 도출할 수 있는지를 판단한다. 차이점이 단순결합, 설계변경, 공지기술부가, 통상최적화에 가까우면 진보성 부족으로 판단한다. 결합 동기가 약하거나 구조/기능 충돌이 있거나 예상 밖 효과가 있으면 진보성 만족으로 판단한다.

### 입력과 출력

입력 구조는 신규성 어댑터와 동일하게 심사대상 문헌과 검색된 선행기술 2건을 붙인다. 다만 작업 지시는 진보성 판단용으로 다르다.

출력은 JSON 형식의 이진 라벨이다.

```json
{"inventive_step":"만족|부족"}
```

## 최종 등록/거절 결합 규칙

신규성 어댑터와 진보성 어댑터는 각각 독립적으로 `만족` 또는 `부족`을 낸다. 최종 등록 여부는 AND 규칙으로 결합한다.

| 신규성 | 진보성 | 최종 판정 |
|---|---|---|
| 만족 | 만족 | 등록 |
| 부족 | 만족 | 거절 |
| 만족 | 부족 | 거절 |
| 부족 | 부족 | 거절 |

이 구조 때문에 최종 추론기는 등록보다 거절을 더 잘 잡는 경향이 있다. 특허 심사 보조 관점에서는 등록 가능성을 과하게 낙관하기보다, 위험한 선행기술 또는 진보성 부족 가능성을 먼저 잡는 보수적 구조다.

## 진보성 부족 서브라벨 멀티라벨 어댑터

### 기능

서브라벨 어댑터는 진보성 어댑터가 `부족`으로 판단한 경우에만 실행된다. 목적은 단순히 거절 여부를 말하는 것이 아니라, 진보성 부족의 성격을 설명 가능한 유형으로 분류하는 것이다.

최종 라벨은 4개다.

| 라벨 | 의미 |
|---|---|
| 결합류 | 여러 선행기술의 결합이 쉽거나 단순결합에 가까운 경우 |
| 차이류 | 차이점이 작거나 실질적 차이가 부족한 경우 |
| 설계변경 | 통상의 설계 변경 또는 균등한 변경에 가까운 경우 |
| 공지기술부가 | 이미 알려진 기술을 단순히 부가한 경우 |

### 입력과 출력

최종 운용에서는 SBERT가 검색한 선행기술 중 TOP1을 사용하고, 간략 입력 형식을 쓴다.

```text
[claim_1]
심사대상 청구항 1 중심 내용

[abstract]
심사대상 초록

[refs_top_K]
[1] 검색된 선행기술 TOP1 요약
```

출력은 4개 라벨에 대한 sigmoid 확률이며, threshold를 넘는 라벨을 복수 선택한다. 만약 threshold를 넘는 라벨이 없으면 확률 상위 2개를 fallback으로 선택한다.

최종 threshold는 다음과 같다.

| 라벨 | threshold |
|---|---:|
| 결합류 | 0.35 |
| 차이류 | 0.30 |
| 설계변경 | 0.30 |
| 공지기술부가 | 0.30 |

### 학습 데이터

서브라벨 데이터는 30,000건 중 `거절-진보성 부족` 샘플 10,000건에서 출발했다. 기존 subtype 라벨이 있는 샘플만 사용했고, 라벨 노이즈가 큰 pseudo default는 제거했다.

| 항목 | 수량 |
|---|---:|
| 진보성 부족 전체 | 10,000 |
| subtype 매칭 | 4,215 |
| 4-class 학습 가능 | 3,318 |
| train | 2,654 |
| validation | 332 |
| test | 332 |

원래 subtype은 4개 대분류로 합쳤다.

```text
결합류       = 결합용이성 + 단순결합
차이류       = 차이없음 + 시너지부정
설계변경     = 설계변경
공지기술부가 = 공지기술부가 + 단순부가
```

수치한정, 균등치환, 기능표현처럼 support가 너무 작은 라벨은 학습 라벨에서 제외했다.

### 학습 방식

서브라벨 모델은 생성형 JSON 모델이 아니라 sequence classification 모델이다.

| 항목 | 값 |
|---|---:|
| base model | `Qwen/Qwen2.5-7B-Instruct` |
| architecture | `AutoModelForSequenceClassification` |
| num labels | 4 |
| loss | `BCEWithLogitsLoss` |
| adapter type | PEFT LoRA, sequence classification |
| dtype | bf16 |
| max sequence length | 4096 |
| per-device batch size | 8 |
| gradient accumulation | 2 |
| effective batch size | 16 |
| epochs 설정 | 5 |
| learning rate | 2e-5 |
| warmup ratio | 0.05 |
| weight decay | 0.01 |
| optimizer | adamw_torch |
| LoRA rank | 16 |
| LoRA alpha | 32 |
| LoRA dropout | 0.05 |
| target modules | q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj |
| modules_to_save | score/classifier head |
| early stopping | macro_f1 기준, patience 5 |

훈련은 grounded-only 데이터로 먼저 진행했다. pseudo-label을 포함하면 데이터 양은 늘어나지만 라벨 노이즈가 커질 수 있기 때문에, 최종 기준 모델은 subtype 근거가 있는 샘플 중심으로 만들었다.

### 성능

서브라벨은 단일 정답 분류라기보다 복수의 거절이유 후보를 제시하는 태스크다. 따라서 exact match보다 Hit@2가 실제 운용에 더 적합하다.

| 평가 기준 | 성능 |
|---|---:|
| 대표 Hit@2 | **92.7%** |
| top1 README concise test Hit@2 | 90.7% |
| Hit@1 | 73.5% |
| Micro F1 | 66.7% |
| Macro F1 | 62.3% |
| Hamming accuracy | 57.4% |

최종 파이프라인에서는 사용자가 요청한 기준대로 Hit@2를 사용한다. 즉, 모델이 제시한 상위 2개 서브라벨 중 실제 라벨이 하나라도 포함되면 맞춘 것으로 본다.

## 설명 생성용 32B 베이스 모델

### 기능

설명 생성 모델은 최종 판정에 관여하지 않는다. 신규성, 진보성, 등록/거절, 서브라벨은 앞단의 판정 모델들이 이미 결정한다. 설명 생성 모델은 그 결과와 검색된 선행기술을 사용자가 이해하기 쉬운 문장으로 정리하는 역할만 한다.

### 사용 방식

설명 생성에는 `unsloth/Qwen2.5-32B-Instruct` 베이스를 사용한다. 신규성/진보성 LoRA가 로드된 상태에서도 설명 생성 시에는 LoRA adapter를 비활성화한다. 이렇게 한 이유는 분류용 LoRA가 설명 문체를 과도하게 제한하지 않도록 하기 위해서다.

입력은 다음 정보로 구성된다.

- 심사대상 문헌
- 검색된 선행기술 2건
- 신규성 판정값
- 진보성 판정값
- 최종 등록/거절 판정값
- 진보성 부족 서브라벨

출력은 사용자용 한국어 설명이다. 웹 서버에서는 `D1`, `D2`, `TOP2 선행문헌` 같은 내부 표현을 후처리하여 `선행기술`이라는 표현으로 정리한다.

### 성능과 역할 구분

설명 생성 모델은 분류 정확도를 계산하는 모델이 아니므로 별도의 accuracy 지표를 최종 성능에 포함하지 않는다. 최종 등록/거절 정확도 87.5%와 타이트 정확도 86.3%는 설명 생성 전에 이미 확정된 판정값 기준이다. 설명 모델의 품질은 사용자가 이해할 수 있는 결론, 신규성 설명, 진보성 설명, 거절 사유 설명을 안정적으로 생성하는지로 확인한다.

## 최종 웹 추론기

최종 웹 추론기는 사용자가 웹페이지에서 발명의 명칭, 초록, 청구항을 입력하고 결과를 확인하는 형태로 구성되어 있다.

웹 추론기의 중요한 구현 포인트는 다음과 같다.

- 제목이 비어 있어도 학습/평가 포맷과 동일하게 `[발명의 명칭]` 블록을 유지한다.
- SBERT, 32B 모델, 7B 서브라벨 모델은 요청 때마다 새로 로드하지 않고 서버 안에서 캐시한다.
- GPU 안정성을 위해 추론 작업은 서버 내부 lock으로 직렬화한다.
- 최종 화면에는 신규성, 진보성, 등록/거절, 서브라벨, 설명만 보여준다.
- 검색된 선행기술 상세 원문은 사용자 화면 아래에 따로 붙이지 않는다.

## 결론

현재 최종 추론기는 선행기술 검색, 신규성 판단, 진보성 판단, 진보성 부족 세부 분류, 사용자용 설명 생성을 하나의 파이프라인으로 통합했다. 사용자가 발명의 명칭, 초록, 청구항을 입력하면 SBERT 검색 모델이 약 29,794건의 선행기술 corpus에서 직접 top2 선행기술을 검색하고, 검색된 선행기술을 기반으로 32B 신규성 어댑터와 32B 진보성 어댑터가 각각 만족/부족 여부를 판단한다. 이후 두 판단 결과를 AND 규칙으로 결합하여 최종 등록/거절 여부를 결정한다.

최종 등록/거절 정확도는 87.5%이고, 멀티라벨까지 포함한 타이트 정확도는 86.3%다. 이 성능은 정답 선행문헌을 수동으로 제공한 조건이 아니라, SBERT가 직접 검색한 선행기술을 입력으로 사용한 end-to-end retrieval 조건에서 측정한 값이다. 따라서 해당 성능은 선행기술 검색 단계의 오류와 신규성·진보성 판단 단계의 오류가 모두 반영된 실제 운용 기준 성능으로 해석할 수 있다.

SBERT는 strict ID 매칭 기준으로는 낮아 보일 수 있지만, 0.995 분위 기준 soft Hit@2는 85.1%로 선행기술다운 후보를 상당히 잘 가져온다. 또한 서브라벨 분류기는 Hit@2 기준 92.7%로, 진보성 부족 사유를 설명용 라벨로 제시하는 데 충분히 강한 성능을 보인다.

따라서 이 시스템은 단순한 LLM 분류기가 아니라, 사용자가 입력한 특허 청구항에 대해 선행기술 검색부터 등록/거절 예비 판단, 거절 사유 세부 분류, 사용자용 설명까지 한 번에 제공하는 end-to-end 특허 심사 보조 파이프라인으로 사용할 수 있다. 특히 최종 정확도 87.5%는 검색과 판단이 모두 포함된 실제 운용 조건에서 얻은 결과이므로, 전체 시스템의 실용 가능성을 보여주는 핵심 지표로 볼 수 있다.
