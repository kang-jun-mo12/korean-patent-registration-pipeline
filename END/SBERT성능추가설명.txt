# SBERT 선행기술 검색 모델 정리

## 최종 사용 모델

최종 사용 모델은 2-stage hard-negative fine-tuning을 적용한 SBERT 모델이다.

```text
model_dir: models/sbert_patent_h200_hardneg_stage2
index_dir: index/sbert_patent_h200_hardneg_stage2
base_model: jhgan/ko-sroberta-multitask
max_seq_length: 512
```

이 모델은 사용자가 입력한 특허의 `발명의 명칭 + 초록 + 청구항 1`을 기준으로, `corpus_unique` 전체 선행문헌 중 의미적으로 가까운 후보를 검색하기 위한 모델이다.

단, raw 데이터상 target의 발명의 명칭이 비어 있는 경우가 많아 실제 학습 데이터에서는 target 54,000 pair 중 18,040 pair만 `[발명의 명칭]` prefix를 포함했다. prior corpus 쪽은 `발명의 명칭 + 초록 + 청구항` 구조를 사용한다.

## 학습 방식

기존 단순 positive pair MNRL에서 한 단계 더 나아가, 다음 방식으로 학습했다.

1. Stage 1
   - 60,000 positive pair 중 train 54,000 pair 사용
   - loss: `MultipleNegativesRankingLoss`
   - batch_size: 256
   - epochs: 3
   - lr: 2e-5
   - output: `models/sbert_patent_h200`

2. Hard Negative Mining
   - stage1 모델로 각 target에 대해 `corpus_unique` 전체 검색
   - 정답 D1/D2가 아닌 문헌 중 rank 20~200 구간에서 hard negative 선택
   - query당 hard negative 3개 사용
   - output: `data/train_pairs_hardneg_stage2.jsonl`

3. Stage 2
   - 입력 형식: `(anchor, positive, hard_negative1, hard_negative2, hard_negative3)`
   - loss: `CachedMultipleNegativesRankingLoss`
   - batch_size: 256
   - mini_batch_size: 32
   - epochs: 2
   - lr: 1e-5
   - output: `models/sbert_patent_h200_hardneg_stage2`

## 성능 결과

평가는 eval target 3,000개를 기준으로, `corpus_unique` 29,794개 전체에서 정답 D1/D2 중 하나라도 top-k 안에 들어오는지를 측정했다.

| 모델 | recall@1 | recall@2 | recall@3 | recall@5 | recall@10 |
|---|---:|---:|---:|---:|---:|
| Stage 1 SBERT | 0.272333 | 0.380667 | 0.459667 | 0.552667 | 0.669667 |
| Hard-negative 1epoch | 0.287000 | 0.401333 | 0.479000 | 0.577000 | 0.692333 |
| Hard-negative 2epoch 최종 | **0.293667** | **0.406667** | **0.486667** | **0.579667** | **0.696000** |

최종 모델은 stage1 대비 다음만큼 개선되었다.

```text
recall@1  +0.021334
recall@2  +0.026000
recall@3  +0.027000
recall@5  +0.027000
recall@10 +0.026333
```

recall@2 기준으로 보면, 정답 D1/D2 중 하나라도 top2에 들어온 query 수가 `1142/3000`에서 `1220/3000`으로 증가했다.

## 수치 해석

겉으로 보면 `recall@2 = 40.67%`가 낮아 보일 수 있다. 하지만 이 평가는 “라벨에 적힌 정확한 D1/D2 문헌 ID가 top2에 들어왔는가”만 인정하는 strict metric이다.

특허 선행기술 검색에서는 같은 기술분야에 매우 유사한 선행문헌이 여러 개 존재할 수 있다. 이 경우 모델이 라벨 D1/D2와 다른 문헌을 가져오더라도, 그 문헌이 정답 선행과 의미적으로 매우 가까우면 실무적으로는 타당한 후보 선행일 수 있다.

이를 확인하기 위해 최종 모델의 검색 결과와 정답 선행문헌 간 유사도를 추가 분석했다.

## 선행문헌 유사도 기반 분석

랜덤 선행문헌 쌍의 cosine similarity 분포는 다음과 같다.

```text
random prior pair similarity p99   = 0.281478
random prior pair similarity p99.5 = 0.326012
random prior pair similarity p99.9 = 0.436391
```

반면 strict top2 실패 케이스만 보더라도, top2 검색문헌과 정답 D1/D2 사이의 최대 유사도 중앙값은 다음과 같다.

```text
top2 strict misses only median similarity to gold prior = 0.461219
```

즉 정확한 D1/D2 ID를 top2에 넣지 못한 실패 케이스의 절반 이상에서도, 모델이 가져온 top2 문헌은 랜덤 선행문헌 99.9%보다 정답 선행에 더 가까웠다.

soft 기준으로 보면 다음과 같다.

| 인정 기준 | top2 hit rate |
|---|---:|
| 정확한 D1/D2 ID만 인정 | 0.406667 |
| 정답 선행과의 유사도가 random p99 이상이면 인정 | 0.889333 |
| 정답 선행과의 유사도가 random p99.5 이상이면 인정 | 0.851000 |
| 정답 선행과의 유사도가 random p99.9 이상이면 인정 | 0.729667 |

따라서 strict recall@2는 실제 후보 검색 유효성을 과소평가할 가능성이 크다.

## IPC 기준 보조 근거

검색 결과가 같은 기술분야 주변에서 형성되는지도 확인했다.

```text
top2 exact-or-same-IPC-class rate = 0.887333
top5 exact-or-same-IPC-class rate = 0.951000
```

IPC overlap은 법적 타당성 판단을 대체하는 지표는 아니지만, 검색 결과가 정답 선행과 같은 기술분야에 모여 있다는 설명 근거로 사용할 수 있다.

## 결론

최종 SBERT 모델의 strict recall@2는 40.67%지만, 이는 라벨 D1/D2 문헌 ID와의 정확 일치만 인정하는 보수적인 수치다.

분석 결과, strict top2 실패 케이스에서도 검색된 문헌이 정답 선행과 의미적으로 가까운 경우가 많았고, top2 검색 결과의 88.73%는 정답 선행과 같은 IPC class를 공유했다.

따라서 이 모델은 단순히 정답 ID를 맞추는 수준을 넘어, 정답 선행과 기술적으로 가까운 대체 후보 선행을 상당수 검색하고 있다고 볼 수 있다. 실제 downstream에서는 SBERT top2 또는 top5 후보를 Qwen 신규성/진보성 판단 모델에 넘기는 방식으로 사용하는 것이 타당하다.
